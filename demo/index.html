TimeNet Hackathon · Round 1

Reading oil wells with a time-series language model

Abnormal events in offshore oil wells, such as hydrate blockages, flow instability or a spurious safety-valve closure, cost production and raise safety and spill risks. We onboarded Petrobras' 3W dataset into TimeNet and fine-tuned OpenTSLM to recognize the event from a well's sensors, then evaluated it on wells it has never seen.

Explore test windows

Each window is 30 minutes of six sensors of a real well, resampled every 10 seconds. These wells were never seen in training. Pick an event type and a window to compare the true event with the answers of OpenTSLM and of the classical baseline. Right and wrong answers are both shown.

Results on wells never seen

Test split of 8 wells held out by well, used once at the end. Macro-F1 averages the F1 of the 6 event types with the same weight. Event recall is the share of event windows flagged as any event; false alarms are the share of normal windows flagged as an event.

Why the evaluation is split by well

The same model on the same windows, cross-validated three ways. Splitting windows at random lets overlapping windows of one recording land on both sides; keeping recordings together still leaks the well. Only a split by well measures how a model does on a new well, so all our numbers use it.

XGBoost baseline, 5-fold cross-validation on the training and validation wells. Error bars: standard deviation over the folds.

How early is an event flagged? Windows slid across the event onset (validation wells, XGBoost baseline, averaged over event types). Dashed line: false alarms on normal windows.

Does a model read the signal, or only its summary statistics?

OpenTSLM receives each series normalized, with its mean and standard deviation written in the prompt. A model could answer from those numbers alone. We test it by perturbing the inputs: shuffling the time order, replacing the series with noise of the same statistics, or swapping the series or the statistics with those of another event.

The same tests on OpenTSLM are running now and will be added here. The check above on the classical baselines shows the tool works: the shape model collapses when the time order is shuffled, while the statistics-only model does not notice.

What these results can and cannot show

  • Few wells per event. In the test split, three event types come from a single well each, so per-class scores rest on one to three events.
  • OpenTSLM and the baseline are statistically tied on macro-F1, while OpenTSLM raises far more false alarms. OpenTSLM is better on the two hydrate events, where the baseline almost always fails, and misses flow instability entirely.
  • Early warning holds only for some event types in the lead-time analysis so far.
  • Explanations: this model answers with the event type only; a version trained with checked explanations is in progress.
